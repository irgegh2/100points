# Скачивание записей с видеоплатформ

Под плеером внешнего видео появилась кнопка «Скачать видео». Она использует
сохранённую в уроке ссылку (`video_source=link`) YouTube, Rutube или VK.
Преподавателю не нужно загружать отдельный файл. Другие источники и собственный
плеер не затрагиваются.

## Как работает

1. `platform_video_prepare.php` проверяет сессию, доступ к курсу, дату открытия
   урока и родительского урока, пререквизиты. URL берётся из базы, произвольный
   адрес клиент передать не может.
2. yt-dlp получает ссылки на дорожки; выбирается MP4 до 720p. Подписанная ссылка
   действует не более десяти минут и привязана к пользователю, уроку и источнику.
3. `platform_video_download.php` повторяет проверку доступа и передаёт через
   FFmpeg MP4 со звуком в обычную загрузку браузера. Видео не перекодируется.
   Браузер не собирает многочасовой Blob в памяти.

Полные видео на сервере не сохраняются. В приватном каталоге
`video_account_root()/platform-downloads` находятся только метаданные ссылок
(права 0600, каталог 0700) и файлы блокировок. Метаданные переиспользуются пять
минут, старые JSON удаляются при последующих подготовках после 30 минут.
Временные файлы проверки фрагментов удалены после проверки.

Одновременно разрешены две подготовки и две передачи для всего аккаунта
хостинга, по одной подготовке и передаче на пользователя. Передача прекращается
при отключении клиента или через два часа. Записи длиннее восьми часов,
незавершённые эфиры и DRM не поддерживаются. Докачки с позиции/HTTP Range нет:
при обрыве нужно начать заново. Платформы могут менять доступность и ограничивать
выдачу; постоянная работоспособность внешних ссылок не гарантируется.

## Установленный runtime

Приватный общий каталог `video_account_root()/bin`, вне webroot:

- `yt-dlp` 2026.10.21, официальный самостоятельный Linux x86_64 бинарник;
- `video-node` v22.23.4, отдельный JavaScript runtime для yt-dlp;
- уже установленные `ffmpeg` и `ffprobe`.

yt-dlp загружен из официального GitHub release, Node — с nodejs.org; SHA-256
сверены с официальными списками. Системный Node не заменён. Обновлять runtime
следует из тех же источников с проверкой хешей. Конфиги и плагины yt-dlp отключены;
куки личных аккаунтов не используются. TLS-проверка включена. Для вложенных HLS
сегментов OpenSSL получает системный CA bundle через SSL_CERT_FILE; FFmpeg
дополнительно получает ca_file. При необходимости можно установить актуальный
CA bundle в приватный `bin/video-cacert.pem`, проверив официальный SHA-256.

## Фактический результат 22 октября 2026

- Rutube: реальный урок 152, исходная запись 11055 секунд. Трёхсекундный фрагмент
  успешно передан как MP4; ffprobe подтвердил H.264 1280×720 и AAC со звуком.
- VK: сохранённая ссылка реального урока 157, исходная запись 7002 секунды.
  Трёхсекундный MP4 подтвердил H.264 1280×720 и AAC. В самом уроке выбран
  собственный плеер, поэтому кнопка внешнего источника там не показывается;
  тип источника и данные урока при проверке не изменялись.
- YouTube: запись урока 236 недоступна **с текущего хостинга**: тайм-ауты на
  www.youtube.com и youtubei.googleapis.com, включая IPv4 и запрос без веб-страницы.
  Извлечение реализовано, но успешное скачивание YouTube не подтверждено.
  Для устранения сетевого ограничения может понадобиться отдельный сервер
  с доступом к YouTube; он не подключён. Пользователю показывается ошибка,
  а успешное скачивание не обещается.

Полные записи для проверки не скачивались, данные учеников не изменялись.
Ключи и подписанные медиассылки в репозиторий не включены.
