# Личный ChatGPT для сайта и GitHub

## Возможности сайта

- `findLessons`: предметы, курсы, периоды, разделы, поиск и постраничное чтение уроков; фильтры по предмету, курсу, периоду, дню месяца и датам эфира.
- `readLearningContent`: полный постраничный доступ к учебным сущностям из белого списка, включая банк заданий, правильные ответы, решения, материалы и тренажёр. Вызов без entity возвращает перечень сущностей и полей.
- `getLesson`: контекст урока, домашки, материалы и тайм-коды.
- `getHomework`: условия, варианты, ответы, решения, вложения и текущая ревизия.
- `saveHomework`: создание домашки с заданиями и решениями либо заполнение существующей пустой домашки. Поддерживаются single, multi, text, textarea, file, audio и ссылки на уже загруженные вложения.

Это административный доступ к учебным материалам, в том числе к ответам. Храни GPT личным. API не открывает пользователей, ученические ответы, сообщения, платежи, сессии или серверные настройки; произвольных SQL и shell-команд нет.

Изменение существующей пустой домашки требует её ID и актуальной revision. Непустые домашки не переписываются; повтор того же содержимого не создаёт дубликат. Новые бинарные файлы эта версия не загружает: картинки и документы нужно предварительно загрузить через админку. Без аутентификации каталог и решения недоступны.

## Однократная настройка GPT

1. Создай личный Custom GPT и включи анализ данных для работы с PDF и подготовки файлов.
2. Скопируй содержимое [instructions.md](instructions.md) в инструкции GPT.
3. В Actions импортируй схему [openapi.json](openapi.json). На рабочем сайте её адрес: `https://100-points.ru/gpt-openapi.json`.
4. В Authentication выбери API Key → Bearer и вставь отдельный ключ интеграции сайта. В схеме и репозитории самого ключа нет. Сохранённая локально копия ключа: `.env.gpt-actions.local` (игнорируется Git).
5. Сохрани GPT с доступом только для себя. ChatGPT может отдельно запрашивать подтверждение записи — это поведение платформы, а не дополнительный шаг нашего API.
6. Для совместной работы с кодом добавь второй Action из [github-openapi.json](github-openapi.json). В его авторизации нужен отдельный GitHub fine-grained token, ограниченный репозиторием `irgegh2/100points`, с Contents: Read and write и Pull requests: Read and write. Metadata: Read-only добавляется GitHub автоматически. Не используй ключ сайта вместо GitHub-токена.

Подключение в конкретном интерфейсе зависит от доступности Custom GPT/Actions для аккаунта. API само по себе не меняет лимиты ChatGPT.

## Общая работа с репозиторием

Репозиторий: https://github.com/irgegh2/100points. Оба помощника читают свежий main, работают в ветках codex/... и описывают изменения в PR. GitHub не синхронизирует автоматически данные MySQL: изменение домашки через сайт и изменение исходника в GitHub — отдельные действия.

Для версии домашки в GitHub используй `content/homeworks/<id>.json` без ключей и персональных данных. Это экспорт для истории; актуальное состояние перед следующей правкой нужно снова читать через API.

## Серверная настройка

Код — `api/gpt_helpers.php`, `gpt_catalog.php`, `gpt_content.php`, `gpt_lesson.php`, `gpt_homework.php`. В `secrets.prod.php` требуется `gpt_actions_key_hash`: SHA-256 случайного Bearer-ключа длиной 32–128 символов из A–Z, a–z, 0–9, `_`, `-`. Для локальной разработки можно задать `GPT_ACTIONS_KEY_HASH`.

Хранится только хеш ключа. Отсутствующий хеш отключает интеграцию с 503; неверный ключ получает 401. Ключ можно отозвать удалением хеша; замена хеша требует обновить Authentication в GPT.

Временные выгрузки, рабочие ключи, дампы и ученические файлы в публичный репозиторий не включаются.
